# UX21 Footprint reference and baseline audit

Reviewed on 2026-11-10 against the Tips-era implementation at local baseline `70a65e1`. The user brief and two supplied production screenshot crops define the starting symptoms. The ATAS findings come from public documentation, API contracts and documentation images. The official video channel was located, but its playback was not available in the reference retrieval. ATAS source code, private algorithms and undocumented behavior were outside the evidence.

## Root causes in the Tips-era baseline

1. `LeftFootprintExecutionPane.tsx` builds x positions from an evenly spaced index in the current slice. Unlinked mode always slices from the end and drag calls the parent pan callback. Linked mode truncates the candlestick range at a separate bar count. A single visible time domain owned by Footprint should drive coordinates, ticks, selection and studies.
2. The left pane preallocates every bin spanning OHLC with bid and ask set to zero. The renderer prints two decimals at small font size and paints a minimum width even when a side has zero volume. This explains both empty rows and small nonzero prints that look identical in the supplied screenshot. The same path substitutes OHLC-shape-weighted volume when captured tape is missing. The sum of the distributed side volumes is not guaranteed to match the kline taker-buy amount.
3. The left pane assigns cells by rounding source midpoint into a new display step. When the step is misaligned with the captured bin width, it cannot locate the underlying trades. It also retains earlier imbalance flags after merging. Its map stores one segmented snapshot per opening time, so later segments overwrite earlier ones in the same candle.
4. The footer mixes candle-level OHLC volume with delta derived from the displayed rows. `MarketStructureChart.tsx` independently builds the inspector's single-bin approximation at the candle close. Thus a selected candle can show a POC and delta that disagree with its chart. Render, inspector, CVD and statistics require a common source, explicit quantity units and coverage.
5. The price axis defaults to the main chart range. Vertical scaling already exists, but y mapping is duplicated between paint and hit tests. The overlay resolves time with a tolerance instead of checking the selected interval. Optional time linking must map by canonical time while preserving each pane's vertical transform.
6. The old Heatmap mode fills a cell using the latest book depth when present, falling back to executed volume elsewhere. Resting liquidity and executions are different quantities. Keep separate provenance and legends if both studies remain available.
7. `CalmMarketTerminal.tsx` supplies the candlestick interval to `useBinanceAggregateTradeCapture`. Changing config stops the worker and starts a new session. The baseline true-flow schema supports 1m, 5m, 15m, 1h, 4h and 1d. M30 requires explicit interval support or valid rebucketing from retained data.
8. `true-flow-session.ts` aggregates trades incrementally but rebuilds and validates the full retained snapshot. The worker's nominal flush interval is 250 ms. The prior [UX16 and UX17 audit](../audit/UX16_UX17_INDEPENDENT_AUDIT_2026-11-06.md) recorded 165 ms for one synthetic 5,000-trade snapshot on its test machine. That is historical evidence of a possible bottleneck and does not measure UX21 frame times.

## Data integrity and target seams

- **Source and continuity.** Preserve the Binance Spot BTCUSDT aggregate-trade worker, validated trade classifier, duplicate/out-of-order checks and gap boundaries. Binance supplies exchange trade time, event time, aggregate ID, first/last trade IDs, price, quantity and buyer-maker flag. Buyer as maker means seller aggressed at the bid. BTC is base quantity and USDT is quote currency. The capture model increments its trade counter once per aggregate event. Label that count as aggregate trades unless underlying fills are separately validated. [Binance aggregate trade stream](https://developers.binance.com/en/docs/catalog/core-trading-spot-trading/api/ws-streams/#aggregate-trade-streams)
- **Price precision.** Use actual symbol `PRICE_FILTER.tickSize` when available. Keep exchange tick, captured base bin and display grouping distinct. An already-binned cell can only be aggregated exactly into aligned wider groups. Label or reject incompatible settings. Test exact bin boundaries, single-side zero, signed neutral delta, and volume conservation to a declared tolerance. [Binance symbol filters](https://developers.binance.com/en/docs/products/spot/filters#price_filter)
- **History.** Binance publishes daily and monthly Spot aggregate-trade archives. Spot archive timestamps switch to microseconds from January 1, 2025. This source is an ingestion candidate. The chart's kline history endpoint does not supply those trades, and availability of the archives does not establish terminal coverage. Archive acceptance requires checksum validation, ID deduplication, timestamp normalization, complete coverage reconciliation and an explicit current-day handoff. [Binance public data](https://github.com/binance/binance-public-data/)
- **Candle calculation.** Retain the true-flow math and session contracts as the observed data source. Derive normalized display bars with sparse bins. Sum buy, sell and count once. Delta is ask minus bid. Delta percentage is delta divided by observed total volume when volume is positive. Define Max/Min Delta by the measured domain. If the calculation uses row deltas, label them as level extrema. A running intrabar delta extreme needs chronological trade order. Preserve gap boundaries in CVD. Do not substitute full OHLC volume for the observed totals of a partial candle.
- **Controller and rendering.** Own interval, time domain, price range, preferences, selected candle and price level in the Footprint controller. A pure projection maps that domain to x coordinates for canvas, time axis, statistics and CVD. Use a separate pointer layer so hover does not rebuild cell geometry. Draw observed clusters, semantic zoom states and OHLC fallback geometry. Store chart settings separately from tape.
- **Integration.** Reuse the terminal shell and divider, Binance kline queries, existing chart coordination primitives, CVD integration and replay clock where applicable. Keep research acceptance, implemented software and live data coverage separate in Project Control.
- **Evidence gates.** Verify H1/H4 with deterministic high-density executions, exact hand-calculated totals and distinct incomplete bars. Measure real browser frame time and pointer latency at a stated viewport, DPR and dataset size. Report p50/p95 frame intervals, browser and hardware. Aim for 16.7 ms frames under normal interaction. Record measurements, not a 60 FPS claim inferred from source. Require before/after captures and interactive desktop and narrow-viewport validation before release acceptance.

## Baseline snapshot timing

On the scratch host (AMD EPYC 9V74, Node 24.22.1), the true-flow session pinned to baseline commit `70a65e1` serialized 5,000 deterministic accepted BTCUSDT aggregate prints with a 10 USDT captured bin. The sample generated one print every 10 seconds, alternating buyer-maker flags, prices distributed over 70,000–74,999 USDT, and quantities of 0.001–0.019 BTC. Each test discarded five warm-ups and measured 20 calls to `TrueFlowSessionAccumulator.snapshot` with `performance.now()`. Quantiles used nearest rank.

| Interval | Bars | Price cells | Snapshot p50 | Snapshot p95 |
| --- | ---: | ---: | ---: | ---: |
| H1 | 14 | 4,737 | 53.20 ms | 63.06 ms |
| H4 | 4 | 2,000 | 23.69 ms | 28.33 ms |

The probe measures worker-side construction and validation without browser paint, message transfer, React reconciliation, or pointer interaction. This baseline does not establish a rendering frame rate or a UX21 performance improvement.
